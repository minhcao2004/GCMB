3. Database Design

3.1 Introduction and Rationale for Choosing PostgreSQL

PostgreSQL is an open-source relational database management system. GCMB chose it because foreign keys keep bookings, bills and payments linked, and transactions let related updates succeed or roll back together.

3.2 pgAdmin 4

pgAdmin 4 provides a graphical interface for connecting to PostgreSQL and inspecting schemas, columns, constraints and views. Query Tool allows the team to run SQL and inspect its results. ERD Tool can visualize table relationships. The database records shown in pgAdmin are stored on the PostgreSQL server.

3.3 What PostgreSQL Stores

| Feature | Data stored in PostgreSQL |
| --- | --- |
| FE-01 | Branch and room configuration, pricing, combos, accounts, role and permission mappings, password and token hashes, audit events, and attachment metadata. |
| FE-02 | Booking identifiers, guest contact details, reservations, room assignments, usage and charges, bills, deposits, payment and refund records, and tax invoice requests. |
| FE-03 | Menu items, room-linked F&B orders, inventory quantities and movements, equipment details, incident and repair history, and references to supporting files. |
| FE-04 | Employee profiles and payout account details, shift schedules, attendance, pay rates, payroll results, salary advances, payment records, and proof metadata. |
| FE-05 | Financial accounts, bank transactions, cash closings, fund transfers, expense requests, approvals, allocations, ledger entries, and reporting source records. |

3.4 File Metadata and Object Storage

The PostgreSQL attachment table stores an internal UUID in attachment.id and the file’s storage key in attachment.object_key. It also stores original_name, mime_type, byte_size, sha256, uploaded_by and created_at. A business record can reference attachment.id, for example through refund_request.evidence_id or asset.image_attachment_id. Some workflows store file references directly in their own tables. Examples include menu_item.image_object_key, finance_attachment.object_key and salary_payment_evidence.object_key.

The storage provider holds the actual image or document bytes. GCMB uses Cloudinary when enabled, and the production configuration enables it by default. The project’s deployment notes record a successful private PNG upload and retrieval test. Supported examples include menu and equipment images, stock receipt evidence, refund proof, payroll proof and expense documents. Some workflows can use local disk.

Cloudflare R2 is an optional S3-compatible storage provider for GCMB upload paths that support an S3 bucket. When configured for R2, the application can store the object bytes in the bucket and retain the object key in PostgreSQL. R2 can store video objects as a platform capability. The GCMB evidence and equipment upload validators support JPEG, PNG, WebP, HEIC, HEIF and PDF.

3.5 Table Dictionary by Feature

Each table block lists its purpose and all schema columns. PK means primary key, FK means foreign key, UNIQUE means a uniqueness constraint, CHECK means a validation rule, and EXCLUDE means an exclusion constraint. NOT NULL requires a value. TIMESTAMPTZ means TIMESTAMP WITH TIME ZONE. A composite key applies to the combination of named columns. Referenced tables belong to the feature in which their own table block appears.

- expense_class_snapshot_check: class_snapshot IN ('OPEX', 'CAPEX')
- expense_status_check: status IN ('DRAFT', 'SUBMITTED', 'APPROVED', 'REJECTED', 'PAID', 'CANCELLED')

3.6 Reporting and Balance Views

The following views expose derived results from existing relations. Each line lists the view, its purpose, its source relations and the output column types.

cash_handover_movement
Represents cash movements derived from operating cash handovers.
Source relations: cash_closing_handover, daily_cash_closing
Columns: id TEXT, account_id UUID, time TIMESTAMPTZ, amount NUMERIC, kind TEXT, description TEXT

daily_till_movement
Combines daily till activity represented by cash closings, their reports and cash remittance.
Source relations: branch, cash_closing_report, cash_closing_report_revision, cash_drawer_remittance, daily_cash_closing
Columns: id TEXT, account_id UUID, time TIMESTAMPTZ, amount NUMERIC, kind TEXT, description TEXT

drawer_funding_movement
Projects drawer funding as cash movements.
Source relations: cash_drawer_funding
Columns: id TEXT, account_id UUID, time TIMESTAMPTZ, amount NUMERIC(18,0), kind TEXT, description TEXT

v_account_balance
Calculates balances for financial accounts using payments, ledger entries and cash movements.
Source relations: cash_handover_movement, daily_till_movement, drawer_funding_movement, financial_account, financial_entry, financial_transaction, payment
Columns: id UUID, code VARCHAR(60), branch_id UUID, balance NUMERIC

v_bill_balance
Calculates remaining bill balances after applied deposits, payments and adjustments.
Source relations: bill, business_adjustment, checkout_cash_reclassification, deposit_entry, payment
Columns: id UUID, booking_id UUID, net_amount NUMERIC(18,0), deposit_applied NUMERIC, payments NUMERIC, remaining_due NUMERIC

v_cash_variance_alert
Surfaces daily cash closing variance and its resolution status.
Source relations: daily_cash_closing
Columns: id UUID, branch_id UUID, business_date DATE, variance NUMERIC(18,0), explanation TEXT, status VARCHAR(20)

v_deposit_balance
Calculates the balance associated with each booking deposit.
Source relations: deposit, deposit_entry
Columns: id UUID, booking_id UUID, balance NUMERIC

v_expense_recognition
Projects recognized expense amounts by period for reporting.
Source relations: finance_expense_allocation, finance_expense_request, finance_recurring_expense_period
Columns: request_id UUID, branch_id UUID, category_id UUID, category_type VARCHAR(5), recognition_mode VARCHAR(12), period_month DATE, seq INTEGER, amount NUMERIC
